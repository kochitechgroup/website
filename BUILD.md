# Building the website

The site is built with [Astro](https://astro.build) and [Bun](https://bun.sh), and deployed on Cloudflare Pages. Contributors and coding agents should also read [AGENTS.md](AGENTS.md), which holds the full set of rules.

## Setup

You need Bun 1.4 or newer, plus Node 22 or newer (Astro's CLI runs on it).

```sh
bun install     # installs dependencies and the git hooks
bun run dev     # local dev server at http://localhost:4321
```

## Everyday commands

| Command | What it does |
|---|---|
| `bun run dev` | Dev server with live reload |
| `bun run build` | Production build into `dist/` |
| `bunx astro preview` | Serves `dist/` locally (static files only) |
| `bunx wrangler pages dev dist` | Serves `dist/` with the Pages Function, as production would |
| `bun run check` | Constraint checks over every tracked file |
| `bun test` | Unit tests for the checks and hooks |

## Where things live

| Path | Contents |
|---|---|
| `src/data/site.ts` | Facts about the group: name, email, topics. Edit these here and nowhere else |
| `src/pages/index.astro` | Home page |
| `src/pages/404.astro` | Not-found page |
| `src/pages/llms.txt.ts` | `/llms.txt` for language models and agents, generated from `site.ts` |
| `src/pages/robots.txt.ts` | `/robots.txt`: allow-all, content signals, sitemap |
| `src/pages/index.html.md.ts` | `/index.html.md`, the home page as Markdown |
| `functions/_middleware.ts` | Cloudflare Pages Function: serves the Markdown twin of `/` to clients that ask for `text/markdown` |
| `src/lib/negotiate.ts` | The `Accept` header parsing behind that, with tests |
| `src/layouts/Base.astro` | `<head>`: title, canonical URL, Open Graph, JSON-LD |
| `src/styles/global.css` | Theme tokens (light and dark) and layout |
| `src/assets/` | Images. They are optimised at build time |
| `scripts/checks/` | Constraint rules and their tests |
| `.githooks/` | `pre-commit` and `commit-msg` hooks |

The sitemap (`/sitemap-index.xml`) is generated by `@astrojs/sitemap`.

## Commits

Commit messages follow [Conventional Commits](https://www.conventionalcommits.org), for example `feat: add events page` or `fix(nav): keep the menu open on tap`. The `commit-msg` hook and CI both enforce it.

Before each commit, the `pre-commit` hook runs the constraint checks on staged files, then the unit tests, then a full build. If a check fails, its message says what it found, why the rule exists, and how to fix it.

## Deploying

Cloudflare Pages builds every push:

- `main` deploys to https://kochitechgroup.dev
- any other branch gets a preview URL, `https://<branch>.kochitechgroup.pages.dev`

The Pages build uses `bun run build`, output directory `dist`, and the environment variable `NODE_VERSION=22`.

DNS, redirects, email routing and every other dashboard setting are recorded in [CLOUDFLARE.md](CLOUDFLARE.md). Update it whenever you change something in Cloudflare.
